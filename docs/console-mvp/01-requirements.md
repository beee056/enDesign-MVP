# 01. プロダクト要件定義 — 面談後案内ツール(/console MVP)

> ⚠️ 本文書は前セッションで一度フル作成されたが消失した。以下は確定済みの章立てと要点。

> 次担当は `requirements-source.md` を基に、この章立てで肉付けすればよい。

## 章立て(確定)

1. **プロダクトの前提** — 公開HP作成サービスではない。面談後の案内業務支援ツール。ローカル動作優先。
2. **解決する課題(要件§1)** — 「面談後、顧客ごとに文面を微調整しながら資料・契約・規約・予約・決済リンクを送るのが面倒」の一点集中。
3. **ターゲット(要件§2)** — MVPは個人塾・スクール運営者に最適化。
4. **機能要件(要件§3-1〜§3-7、全7小節)**
   - 4-1 事業者情報管理 / 4-2 書類・リンク管理 / 4-3 案内セット管理 / 4-4 顧客管理(契約フェーズ11種) / 4-5 顧客別案内文生成(トーン7種・出力6項目) / 4-6 送付前チェックリスト / 4-7 フェーズ管理
5. **やらないこと(要件§4)** — 公開ページ/検索/決済代行/予約・電子契約の内製/顧客向けログイン/高機能CRM等。外部サービスのリンク登録で代替。
6. **AI生成機能の仕様(要件§6)** — 方針9項目、生成文構成8ステップ、メール版/LINE版を分離、送付前チェックリスト。
7. **非機能要件・判断基準(要件§12)** — 汎用化より原体験、多機能化より省力化、送付漏れ防止優先、軽い顧客フェーズ管理、外部リンク管理優先、まず個人塾・スクールで検証。
8. **スコープ外・将来(要件§13)** — 他業種テンプレ、書類読取自動化、契約書・規約の不整合チェック等はMVP後。
9. **検討事項** — temperatureの区分定義、顧客種別の入力方式 等(`03-db-design.md`§8と重複する未確定点)。
