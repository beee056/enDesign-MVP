# 02. 画面設計 — 面談後案内ツール(/console MVP)

> ⚠️ 本文書は前セッションで一度フル作成されたが消失した。以下は確定済みの章立て・ルートパス・設計判断。
> 各画面のワイヤーフレーム本文は `requirements-source.md`§5 と `03-db-design.md` から再生成可能。

## 章立てとルートパス(確定)

1. **デザイン方針(要件§9)** — 複雑な業務システムに見せない。Notion的な軽さ。日本語UI。テーブル中心。「自分でも使えそう」。
2. **認証・テナント紐付け方針** — Clerkログインユーザー → `users` → `memberships` → `tenants` でテナントを解決。全データ操作を tenant 境界でフィルタ。
3. **ナビゲーション構成(サイドバー案)** — ダッシュボード / 顧客 / 書類・リンク / 案内セット / 設定。
4. **画面一覧サマリー**
5. **5-1. ダッシュボード** — `/console`
6. **5-2. 顧客一覧** — `/console/clients`
7. **5-3. 顧客詳細** — `/console/clients/[clientId]`
8. **5-4. 書類・リンク管理** — `/console/doc-links`
9. **5-5. 案内セット管理** — `/console/guide-sets`
10. **5-6. 案内文生成画面** — `/console/clients/[clientId]/messages/new`
11. **5-7. 設定画面** — `/console/settings`
12. **画面遷移図(全体)**
13. **検討事項**

## 主要な設計判断(確定)

- 要件§3-7の「フェーズ別一覧」は独立画面にせず、**顧客一覧内のタブ/フィルタ**として統合。
- 「案内文生成履歴」「次回対応メモ」は**顧客詳細内のセクション**として配置(要件の画面列挙と5-1〜5-7の実画面数の齟齬を整理した結果)。
- 各画面は既存 `src/app/admin/*` のUIパターン(shadcn/テーブル/カード)を踏襲する想定。
