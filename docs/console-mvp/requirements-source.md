# 面談後案内ツール MVP — 要件原文(依頼者プロンプト)

> 本ファイルは依頼者から提供された要件の原文(唯一の正)。設計・実装はこれに従う。
> 補足決定事項(前セッションで依頼者承認): ②は本リポジトリ(enDesign)内の `/console` ルートグループ配下に構築する方針だった。
> `organizations` は既存 `tenants` テーブル(`src/db/schema.ts`)を流用する。
> ※この方針の実装物は一度消失している。詳細は `docs/HANDOFF.md` を参照。

# 1. 作りたいサービスの概要

無料面談・初回相談のあとに発生する、案内文作成・資料送付・契約書送付・規約送付・予約リンク送付・決済リンク送付・契約フェーズ管理をラクにする、小規模サービス事業者向けの業務支援ツール。

これは公開用のホームページ作成サービスではない。一般公開用の事業者ページ、ポータルサイト、検索サービス、集客プラットフォームは作らない。

最初に解くべき課題:
「無料面談後に、顧客ごとにメールやLINEの文面を微調整しながら、料金説明資料・契約書・規約・次回予約リンク・決済リンクなどを送るのが面倒」
——この一点に集中する。

# 2. 最初のターゲット

小規模サービス事業者(個人塾 / スクール / コーチ / コンサル / 士業 / 制作業 / 初回相談や無料面談後に契約・決済・予約案内が発生する人)。
ただしMVPでは業種を広げすぎず、まず **個人塾・スクール運営者** が使いやすい設計にする。

# 3. このサービスでやること

## 3-1. 事業者情報管理
登録項目: 事業者名 / 代表者名 / メールアドレス / 電話番号 / 住所 / サービス概要 / 署名文 / よく使う連絡手段

## 3-2. 書類・リンク管理
登録できるもの: サービス説明資料URL / 料金説明資料URL / 契約書URL / 規約URL / 予約リンク / 決済リンク / 問い合わせフォームURL / LINE URL / その他リンク
各リンクの属性: タイトル / 種別 / URL / 説明文 / 有効・無効 / 最終更新日 / 備考

## 3-3. 案内セット管理
よく送る資料・リンクの組み合わせを「案内セット」として保存。
例: 入塾案内セット / スポット相談セット / 継続契約セット / 追加面談案内セット / 決済待ちリマインドセット
含める項目: セット名 / 説明 / 含める書類・リンク / 推奨する送付タイミング / デフォルト文面テンプレート

## 3-4. 顧客管理
登録項目: 顧客名 / 顧客種別 / メールアドレス / 電話番号 / LINE名またはLINE連絡可否 / 問い合わせ経路 / 紹介者 / 温度感 / 面談日 / 面談メモ / 提案プラン / 次回アクション / 契約フェーズ / 備考
契約フェーズの初期値(11種): 問い合わせ / 面談予定 / 面談済 / 案内文作成中 / 案内送付済 / 契約確認中 / 決済待ち / 次回予約待ち / 契約完了 / 失注 / 保留

## 3-5. 顧客別案内文生成
入力: 顧客名 / 顧客種別 / 問い合わせ経路 / 温度感 / 面談メモ / 提案プラン / 送る案内セット / 文面の長さ / 文面のトーン / 送信媒体
文面トーン(7種): 丁寧 / 簡潔 / やわらかい / 背中を押す / 紹介経由向け / 比較検討中向け / 事務連絡寄り
出力: メール件名 / メール本文 / LINE用短縮文 / 送付リンク一覧 / 次回アクション / 送付前チェックリスト

## 3-6. 送付前チェックリスト
例: 料金説明資料が含まれているか / 契約書が含まれているか / 規約が含まれているか / 予約リンクが含まれているか / 決済リンクが含まれているか / 顧客名が正しいか / 提案プランが正しいか / 古いリンクが含まれていないか

## 3-7. フェーズ管理
必要な画面: 顧客一覧 / フェーズ別一覧 / 顧客詳細 / 案内文生成履歴 / 次回対応メモ

# 4. このサービスでやらないこと(MVP)

一般公開用の事業者ページ / 事業者検索ページ / ポータルサイト / マッチング機能 / 決済代行 / 予約システムの内製 / 電子契約機能の内製 / 顧客向けログイン画面 / 本格的なCRM / 高機能なチャット機能 / SNS投稿機能 / 集客機能 / 公開レビュー機能。

既存の外部サービスを前提にする(リンクを登録するだけ):
- 予約: Googleカレンダー / Calendly / RESERVA / STORES予約 等
- 決済: Stripe / Square / STORES決済 / 銀行振込案内 等
- 電子契約: クラウドサイン / GMOサイン / Google Docs / PDF 等

# 5. 画面構成(最低限)

- 5-1. ダッシュボード: 本日対応が必要な顧客 / フェーズ別件数 / 案内未送付の顧客 / 決済待ちの顧客 / 次回予約待ちの顧客 / 最近作成した案内文
- 5-2. 顧客一覧: 顧客名 / 問い合わせ経路 / 温度感 / 提案プラン / 契約フェーズ / 最終更新日 / 次回アクション。操作: 新規追加 / 詳細へ / フェーズ変更 / 案内文作成
- 5-3. 顧客詳細: 基本情報 / 面談メモ / 提案プラン / 契約フェーズ / 過去の案内文 / 送付済み案内セット / 次回アクション。操作: 編集 / 案内文生成 / フェーズ更新 / メモ追加
- 5-4. 書類・リンク管理: 登録済みリンク一覧 / 種別 / 有効無効 / 最終更新日。操作: 追加 / 編集 / 無効化 / 削除
- 5-5. 案内セット管理: 一覧 / 含まれる書類リンク / デフォルト文面。操作: 作成 / 編集 / 複製 / 削除
- 5-6. 案内文生成: 入力(顧客選択 / 案内セット選択 / トーン / 長さ / 追加メモ)→ 出力(件名 / 本文 / LINE短縮文 / 送付リンク一覧 / 送付前チェックリスト)。操作: コピー / 再生成 / 履歴に保存 / フェーズを「案内送付済」に変更
- 5-7. 設定: 事業者情報 / 署名文 / デフォルト文面トーン / よく使うプラン名 / よく使う外部サービスURL

# 6. AI生成機能の仕様

方針: 過度に営業っぽくしない / 顧客ごとの状況を反映 / 面談内容への言及 / 料金・契約・規約・予約・決済の確認を自然に促す / 不安を煽らない / 押し売り感を出さない / 送付リンクを見やすく整理 / 最後に次のアクションを明確に / メール版とLINE版を分けて出力。
生成文の構成例: 1.面談のお礼 2.面談内容の振り返り 3.提案内容 4.確認してほしい資料 5.契約・規約・決済・予約の案内 6.次のアクション 7.締めの一言 8.署名

# 7. データ設計(想定テーブル)

users / organizations / clients / documents / document_links / guide_sets / guide_set_items / generated_messages / client_phase_logs / settings
各テーブルに原則 organization_id を持たせる(将来の複数事業者対応)。
→ 既存スキーマへの適合方針は `03-db-design.md` を参照(organizations=既存tenants流用、documents+document_links=doc_linksに統合、settings=console_settingsに改名 等)。

# 8. 技術構成

フロント: Next.js / UI: Tailwind CSS / 認証: Clerk / DB: Neon Postgres / ORM: Prisma または Drizzle(本リポジトリはDrizzle) / AI生成: OpenAI API / デプロイ: Vercel。
MVPではまずローカルで動作することを優先。

# 9. デザイン方針

複雑な業務システムに見せない / 小規模事業者でも迷わない / Notion・Googleドキュメントのような軽さ / 画面内文言は日本語 / ボタン・ラベルは直感的 / テーブル中心で情報整理 / 「これなら自分でも使えそう」と思える。

# 10. 最初に入れておくサンプルデータ(個人塾・スクール向け)

- 事業者: 総合型選抜専門塾 LIGHTHOUSE(総合型選抜・推薦入試の志望理由書/小論文/面接/プレゼン対策を行う個別指導)
- リンク: サービス説明資料 / 料金説明資料 / 入塾規約 / 入塾契約書 / 面談予約リンク / 決済リンク / 問い合わせフォーム
- 案内セット: 入塾案内セット / スポット相談案内セット / 継続契約案内セット / 決済リマインドセット
- 顧客: 紹介経由の高温度顧客 / SNS問い合わせの比較検討顧客 / 無料相談だけ希望の低温度顧客

# 12. 重要な判断基準(迷ったら優先)

汎用化より原体験の課題解決 / 多機能化より面談後案内の省力化 / 公開ページより内部業務の整理 / 自動化より送付漏れ防止 / 高機能CRMより軽い顧客フェーズ管理 / 決済・予約・契約の内製より外部リンク管理 / 士業・地方展開よりまず個人塾・スクールで検証。

# 13. 最終的に目指す方向(MVP後・初期は作り込まない)

士業向けテンプレ / コーチ・コンサル向けテンプレ / 制作業向けテンプレ / 書類読み取りによる案内セット自動作成 / AIによる契約書・規約・料金表の不整合チェック / 外部サービス導入支援の提案 / Webページ制作やチャットボット制作へのクロスセル導線。
初期MVForはこれらを作り込みすぎない。まず無料面談後の案内業務をラクにする一点に集中。
